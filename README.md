> 可选联网查询歌手流派，按 **说唱 / 粤语 / 华语 / 摇滚 …** 再分一层。
>
> Windows 10 / 11 · 免安装 · 纯本地运行 · 默认只预览不改文件 · 每步可撤销
> V1.1大概率是最终版本，因为平常我用网易云也只会单曲循环，做这个工具是为了方便NAS存之类的(

## 它能做什么

| 功能 | 说明 |
|---|---|
| **按标签归档** | 读 `artist` / `albumartist` / `album` / `year`，按模板建目录 |
| **合作歌手归并** | `MC法老&Lil G`、`A/B/C`、`周杰伦 feat. 袁咏琳` → 只取**第一位**歌手，不再每个组合各开一个文件夹；内置 26 个保护名单（`Simon & Garfunkel`、`AC/DC` 等）不会被拆 |
| **文件名兜底** | 缺歌手/歌名标签时从文件名解析，并**自动判断谁在前**：`周杰伦 - 晴天` 和 `晴天 - 周杰伦` 都能认对 |
| **联网歌手分类** | 联网查歌手流派，映射成 `说唱 / 粤语 / 华语 / 摇滚 / 电子 / 民谣 …`，用 `{category}` 建目录 |
| **预览表格** | 整理前逐条列出「原文件 → 整理后位置」，靠猜的行标橙色，归并的行标蓝色 |
| **一键撤销** | 每次执行写 `_organize_log_*.jsonl`，可按日志完整还原 |
| **并行 + 缓存** | 多线程读标签；联网结果缓存到本地，第二次运行几乎瞬时 |

**它不做什么**：不对音频波形做分析。风格信息只来自**文件标签**或**联网查询**，详见[已知限制](#已知限制)。

## 分类规则

### 模板字段

`{artist}` `{album}` `{year}` `{title}` `{track}` `{disc}` `{category}` `{albumartist}` `{genre}`

```bat
python cli.py "D:\Music" -d "D:\Sorted" -t "{category}/{artist}/{album}"
```

> ⚠ **模板里必须包含 `{category}`，联网分类才会生效。**
> 程序会主动检查：开启联网分类时若模板里没有它，会弹窗问你自动修改。

### 内置方案

| 方案 | 模板 |
|---|---|
| 分类 / 歌手 / 专辑 | `{category}/{artist}/{album}` |
| 分类 / 歌手 | `{category}/{artist}` |
| 歌手 / 专辑 | `{artist}/{album}` ← 默认 |
| 歌手 / 年份 / 专辑 | `{artist}/{year}/{album}` |
| 歌手 / 专辑 (年份) | `{artist}/{album} ({year})` |

### 取值逻辑

- **歌手**：优先专辑艺术家（合辑归入「群星」），可用 `--no-albumartist` 关闭
- **空字段**：模板中某层为空时**整层跳过**，不会生成 `Album ()` 这种怪目录
- **合法性**：Windows 非法字符、保留名（`CON`/`LPT1`…）、结尾点空格自动清洗；
  重名追加 ` (2)`，**绝不覆盖**

## 联网歌手分类

勾选「联网查询歌手分类」后，程序按歌手名查询流派并映射成大类。**默认关闭，不勾选时完全离线。**

### 数据源与速度

| | 数据源 | 每位歌手请求数 | 实测耗时 |
|---|---|---|---|
| 主力 | **iTunes Search API**（免费公开接口） | **1 次** | 约 0.36 s |
| 兜底 | MusicBrainz WS/2 | 2 次 | 约 2.2 s |

iTunes 返回**结构化流派字段**（`Mandopop`、`Cantopop/HK-Pop`、`Hip-Hop/Rap`），直接映射即可；
失败或查不到时自动回退 MusicBrainz。

**为什么不去爬百度 / 必应**：多数搜索引擎的服务条款禁止自动化抓取；页面改版、
验证码会随时让它失效；而且返回的是网页文本，仍需二次猜测。结构化接口给的是确定值。

### 三层省时间机制

1. **本地标签优先** —— 文件自带 `genre` 且能判定时，这位歌手**根本不联网**
2. **缓存** —— 结果写入程序旁的 `artist_cache.json`，第二次运行几乎瞬时
3. **自适应并发** —— 当网络延迟大于限速间隔时，自动用多线程把等待重叠起来。
   实测：延迟 1.0s 时提速 **2.47 倍**，延迟 0.1s 时无收益也不捣乱。
   关键是**并发不提高请求频率**（发起间隔仍受全局限速控制），所以不会多触发限流

界面显示进度与预计剩余时间，随时可点【取消】：

### ⚠ 三个必须知道的局限

| 局限 | 实例 |
|---|---|
| **同名会认错** | 查 `GAI` 拿到的不是说唱歌手周延，会被归成别的类 |
| **冷门歌手查不到** | 归入「未分类」 |
| **语言/地区只是近似** | 陈奕迅的**国语**专辑也会被归到「粤语」下 |

第三条尤其重要：**按歌手名推不出单张专辑的语言**，这是数据源里就没有的信息。

**解决办法：分类修正表。** 在【识别与归并…】里每行写一条 `歌手=分类`：

```
GAI=说唱
周杰伦=华语
```

修正表**优先于联网结果**，且不触发网络请求。

### 频率上限说明

Apple 对该接口的建议是 **20 次/分钟**，而本程序为了速度实际跑在 **约 170 次/分钟**。
偶尔会碰到 403 限流，此时程序**不会在原地空等重试**，而是立即降到合规速率重试；
若持续被限流，就停用该数据源、改用 MusicBrainz，保证不漏歌手、也不卡住。

## 性能实测

测试环境：Windows 10 19045 / 12 线程 CPU / 2000 个带完整 ID3 标签的 MP3。

### 标签读取

| 版本 | 耗时 | 吞吐 |
|---|---|---|
| 初版 | 5.53 s | 361 文件/秒 |
| **当前** | **2.89 s** | **693 文件/秒** |

**1.91 倍**。最大瓶颈其实是自己的代码：每个文件调用两次 `Path.resolve()`，
在 Windows 上会触发 `nt._getfinalpathname` 系统调用，2000 个文件共 **18094 次调用、
占总耗时 44%**。改为纯字符串归一化后消失。线程并行只贡献 1.13 倍（mutagen 的 ID3
解析在 Python 层，受 GIL 限制），实测超过核数后收益停止并回落，因此默认取 `min(16, 核数)`。

### 启动速度

| | 文件夹版 | 单文件版 |
|---|---|---|
| 启动 | **2.27 s** | 2.79 s（**首次 15 s**） |
| 临时目录 | 不解包 | 每次解包约 16 MB / 900 个文件 |

所以推荐文件夹版。

### 联网分类

12 位歌手首次查询 **4.3 秒**（0.36 s/位），第二次走缓存 **0.01 秒**。

## 安全设计

- **默认预览**，加 `--apply` 才写盘；执行前二次确认
- **可完整撤销**：每次执行生成 `_organize_log_时间戳.jsonl`
- **不自我吞食**：输出目录若在源目录内部，扫描时自动排除
- **绝不覆盖**：重名自动追加 ` (2)`
- **复制保留元数据**：用 `shutil.copy2`
- **联网仅在手动勾选后发生**，且只发送歌手名

## 已知限制

1. **不做音频分析。** 风格来自标签或联网查询，不是"听"出来的。
2. **网络延迟决定体验。** 联网分类受数据源限速约束，网络慢时会更慢。
3. **Windows only。** 依赖 Windows 的文件名规则与 tkinter 行为。
4. **未做数字签名。** 首次运行有 SmartScreen 提示；部分杀软可能对 PyInstaller
   单文件产物误报（文件夹版较少见）。
5. **只识别常见大类。** 流派映射表是关键词规则，冷门细分风格会落到「未分类」。

## 常见问题

**Q：中文标签会不会乱码？**
不会。全程 UTF-8，已针对中文路径与标签测试（`周杰伦 / 叶惠美`）。

**Q：勾了「联网分类」为什么输出里没有分类文件夹？**
几乎只有一个原因：**目录模板里没有 `{category}`**。把模板改成
`{category}/{artist}/{album}` 即可。程序会在启用时主动检查并提醒。

**Q：会不会误删我的歌？**
默认只复制、只读源文件；只有显式选「移动」才会动源文件，且可用日志一键撤销。

**Q：支持哪些格式？**
mp3 / flac / m4a / m4b / aac / ogg / opus / wav / wma / aiff / ape / wv / dsf / dff 等
（取决于 mutagen 支持范围）。

**Q：怎么快速确认环境没问题？**

```bat
音乐分类整理器.exe --selftest %TEMP%\st.txt        :: 自检，结果写入文件
音乐分类整理器.exe --lookup-test 周杰伦 %TEMP%\lk.txt :: 单独测联网查询
```

## 更新日志

### V1.1（当前）

**修复**

- 🐛 **分类不生效**：开启了联网分类，但「内置方案」下拉框与实际目录模板不一致
  （下拉框显示分类方案，模板里却没有 `{category}`），导致查到的分类被丢弃。
  现已让下拉框**始终由实际模板反查得出**，并在启用联网分类而模板缺少 `{category}` 时
  主动弹窗提醒、可一键修正。
- 🐛 联网查询时界面**进度循环被一个异常打断**，导致进度条/日志/完成回调永久停摆，
  界面看起来像卡死。现已在消息级捕获异常并保证重新排期。

**新增**

- 联网分类支持**进度条 + 预计剩余时间 + 取消**
- **本地 `genre` 标签优先**：能判定的歌手不联网（零等待）
- **自适应并发**：延迟大于限速间隔时自动并行，实测提速 2.47 倍且不提高请求频率
- **限流处理**：403/429 立即降速重试，持续被限流则切换数据源，不再空等
- 数据源主力由 MusicBrainz 换成 **iTunes**（每位 1 次请求，约快 6 倍）
- 合作歌手归并、文件名兜底与方向判断、分类修正表

**性能**

- 标签读取 361 → **693 文件/秒**
- 新增文件夹版（推荐）与单文件版双形态发布

### V1.0（首个公开版本）

- 基础标签分类、预览、复制/移动、撤销
